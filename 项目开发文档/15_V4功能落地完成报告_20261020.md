### 3.4 RESTful 设计说明（与文档路径的偏差）

文档 §22.1 的部分路径不含项目上下文（如 `PATCH /voices/{character_id}/params`、
`PATCH /shots/batch`、`POST /assets/batch-regenerate`）。为避免在 URL 里塞
`?project_id=` 这类"伪 REST"参数，本轮统一采用**由资源反查归属项目**再校验 ACL：

| 端点 | 项目来源 |
|---|---|
| `PATCH /voices/{character_id}/params`、`POST /voices/{character_id}/preview` | 角色资产 → `assets.project_id` |
| `PATCH /subtitles/{line_id}` | 字幕行 → `subtitle_lines.project_id` |
| `POST /subtitles/batch-style` | 字幕样式 → `subtitle_styles.project_id`（全局样式须显式传 `project_id`） |
| `POST /timeline/{timeline_id}/bgm/replace` | 时间线 → `timelines.project_id` |
| `POST /assets/batch-regenerate` | 首个资产 → `assets.project_id` |
| `PATCH /shots/batch` | 首个镜头 → `shots.storyboard_id` → 分镜板项目 |
| `POST /render-tasks/batch-retry`、`POST /render-queues/{batch}/jump` | 首个任务 → `render_tasks.project_id` |
| `POST /episodes/{episode_id}/lock-versions` | 集 → `episodes.project_id` |
| `POST /export-jobs/prespec-check` | 显式 `project_id` 查询参数（自检按项目成片时长判定） |

## 七、修复的既有缺陷（开发过程中暴露）

| # | 缺陷 | 现象 | 修复 |
|---|---|---|---|
| 1 | 并发同类型资产生成撞唯一键 | 一次提交多个场景变体时 `uq_asset_versions_asset_id_version_type_version_no` 冲突（500） | 新增 `(asset_id, version_type)` 进程内互斥锁，串行化"版本号分配 → 落库" |
| 2 | 剧本终止未提交 | 无项目状态流转时 `cancel_run` 的变更未落库，重复终止会二次结算并报 30005 | `cancel_run` 末尾显式 `commit()` |
| 3 | `uq_export_jobs_cache_key` 唯一约束阻断合法复用 | 「复用参数重新导出」必然以相同 `cache_key` 新建任务 → 唯一键冲突 | 改为**非唯一索引** `idx_export_jobs_cache_key`（02 文档 §13.5 已同步偏差说明），并补一次性修复脚本 `scripts/fix_export_cache_index.py` |
| 4 | `PATCH /shots/batch` 被 `/shots/{shot_id}` 抢占 | 路由注册顺序导致 `batch` 被当作 `shot_id` 解析 → 10001 | 将批量端点定义前移到参数化端点之前 |
| 5 | 按集锁定静默跳过无版本镜头 | 复制出的新镜头无 `shot_versions` 时被无提示跳过 | 返回 `skipped[]` 并说明"该镜头尚无生成版本，请先生成" |
| 6 | `alembic check` 误判 LangGraph 运行时表 | 每次检查都报"需要 drop_table" | `env.py` 增加 `include_object` 过滤 |
| 7 | 多个端点的 ACL 依赖要求不存在的 `project_id` 路径参数 | 请求直接 10001「project_id: Field required」 | 改为由资源反查归属项目（见 §3.4） |
