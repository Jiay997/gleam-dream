## 0. 执行摘要

- **链路可以走通**：1410 从建项 → AI 剧本 → 资产 → 分镜 → 9 镜 I2V → 配音/字幕 → 合成 → 720p 导出，最终拿到真实 MP4（720×1280、45.5s、含 AAC 音轨、7.1MB），导出可播放。
- **但成片质量不达标**：逐镜联系表与成片抽帧发现 **角色换装/换脸、台词人物错配、首帧拼贴、黑块遮脸、同一镜头被拉长 2 倍** 等穿帮；这些穿帮没有被现有 QC 拦截。
- **语音链路实际未接通**：9 条配音全部落盘在 `/files/voice/stub/*.wav`，`voice_id` 全为 `None`，`ai_call_logs` 中没有任何 TTS 调用记录；qwen-tts 虽配置可用，但未被调用。
- **LLM 链路不稳健**：DeepSeek 503 时不会切换 GLM，剧本生成 1.7 秒内失败并让项目进入 `failed`；重试/取消后的剧本生成会因“最新 run=cancelled”立即自我终止；生成节点出现过连续 8–20 分钟无任何模型调用的挂起。
- **状态机与前端多处脱节**：分镜审批通过后项目卡在 `asset_review`，必须手工逐级 transition 才能渲染；分镜页 9 镜已 `rendered` 却仍显示“暂无镜头视频”。

结论：**不建议进入修复后的验收，必须先修 P0 项**。共记录 24 个问题，其中致命 6 个、严重 10 个、一般 7 个、建议 1 个。

## 3. 链路保真度审计（1.2）

### 3.1 剧本 JSON → 分镜字段

测试剧本 `script_id=906`：1 集 / 3 场 / 1657 字；场 1 宴会厅（6 action + 5 dialogue），场 2 长廊（5 action + 4 dialogue），场 3 长廊（7 action + 5 dialogue）。每个角色首次出场 action 行均带**姓名——服装/发型/道具/机位**，例如：

> 林默——洗得发白的浅灰衬衫，深藏青色旧西裤，略长的黑色短发，额前碎发压着眼睛……道具：胸前的蓝色工牌。机位：固定

这是后续形象锁定词的唯一可信来源，字段完整。

### 3.2 锁定词是否进入每个镜头提示词

分镜 355 共 9 镜，逐镜检查 `final_prompt`：

| 镜头 | shot_size | 场景资产 | 角色资产 | 含“人物造型锁定” | 含场景描述 | 含动作 |
|---|---|---|---|---|---|---|
| S1 | wide | 1143 宴会厅 | 1139 赵德海 | ✓ | ✓ | ✓ |
| S2 | over_shoulder | 1143 | 1140/1139/1138 | ✓ | ✓ | ✓ |
| S3 | close_up | 1143 | 1139/1141/1138 | ✓ | ✓ | ✓ |
| S4 | medium | 1143 | 1138 | ✓ | ✓ | ✓ |
| S5 | wide | 1144 长廊 | 1142/1140/1138/1139 | ✓ | ✓ | ✓ |
| S6 | close_up | 1144 | 1142/1138/1140 | ✓ | ✓ | ✓ |
| S7 | medium | 1144 | 1138/1141 | ✓ | ✓ | ✓ |
| S8 | over_shoulder | 1144 | 1139/1138 | ✓ | ✓ | ✓ |
| S9 | close_up | 1144 | 1140/1139/1138 | ✓ | ✓ | ✓ |

结论：**文本层 ①角色锁定词 ②动作 ③同场景 location 三项均进入 final_prompt**；S1–S4 场景资产一致为 1143，S5–S9 一致为 1144。

### 3.3 实际发给 I2V 的 effective_prompt（渲染任务库里取证）

以 task 886（S1）为例，`render_tasks.input_params->effective_prompt` 含：

- 场景：酒店宴会厅…（与 final_prompt 同源）
- 人物造型锁定（全片不得换装/换发型）：赵德海——男性，40-50 岁…
- 人物动作：赵德海——深灰细条纹西装…双手背在身后…
- 镜头运动：极缓慢推近（幅度≤8%）
- 景别锁定：**全程保持全景构图**（与该镜 `shot_size=wide` 一致）
- 时序变化 + 质量尾缀（不换画风、不出现文字、不变场景）

结论：**④ 发到视频模型的确有动作描述，不是“只有图片”**。代码位置：`backend/app/tasks/executor.py:649-657`。

### 3.4 字段空值下游行为

| 缺失字段 | 当前行为 | 风险 |
|---|---|---|
| 角色未匹配（character_asset_ids 为空） | 提示词无“人物造型锁定”，仍可生成；分镜锁定只要求“角色或场景至少一个” | **高**：完全自由生成，角色必漂移 |
| 场景未匹配 | prompt 省略“场景：…”，仍可生成 | **高**：场景自由生成 |
| 资产 description 为空 | 锁定句被 filter 掉 | **高**：静默丢约束 |
| script_anchor 缺失 | `_build_script_anchor` 用台词/动作兜底；但无“缺锚点禁止生成”的硬校验 | 中：导演锚点语义丢失 |
| duration 不在 3–5s | 渲染前直接 40001 拒绝 | 低（显式报错） |

代码位置：
- 锁定条件仅“角色或场景至少一个”：`storyboard_service.py:2500-2508`
- 锁定句生成依赖 description 非空：`storyboard_service.py:1801-1811`
- 场景缺失静默省略：`storyboard_service.py:1815-1819`

### 3.5 重试一致性

- **seed 不存在**：全仓库 `backend/app/infra/model_gateway` 与 `render_service.py` 均无 seed 字段；`gateway_params` 只传 `duration_ms/aspect_ratio/camera_move/resolution/fps/negative_prompt/...`（`executor.py:596-635`）。
- **重试提示词不一致**：`_execute` 每轮调用 `motion_service.build_motion_prompt(..., round_no=qc_round)`；`round_no>0` 时插入“【强化动态·第 N 次重试】…”，并逐轮改变强化词（`executor.py:643-657`；`motion_service.py:344-346`）。
- **手动 retry 复用**：`retry_task` 复用 `input_params`（含 `base_prompt`），不重复扣款（`render_service.py:1083-1126`）；但提示词仍会按新 `qc_round` 重建，且没有 seed 可复用。
- 结论：**“强制复用首次完整提示词和 seed”未实现**。若目标要求跨重试画面可复现，现状无法保证。

### 3.6 相邻镜头一致性校验

- 同一 `scene_id` 下不同 `scene_asset_id` → `composition_service.py:232-251` 写 `unexpected_scene_change` **warning**，不阻断。
- 不同 `scene_id` 的正常换场不告警。
- **相邻镜头角色是否换装/换脸**：没有硬校验；`continuity_service.py` 的 LR-1/LR-2 只在用户主动跑连续性检查时给出 warning，渲染管道不消费。
- 结论：⑤ “拼接前一致性校验”只覆盖“同场次场景资产”，**不覆盖角色形象**，且所有结果都只是 warning。

### 3.7 核心结论：四道“防穿帮闸门”现状

1. 拼装层缺字段 → 不是显式报错，而是**静默省略**（角色/场景/描述）→ 高风险。
2. 角色锁定词 → 有注入，但**两个拼装点格式不一致**：分镜生成用“人物造型锁定（不得换装/换发型）：名字——描述”；手动 `bind_anchors` 用“出场角色：名字（摘要）”，且**丢掉道具锁定**（`storyboard_service.py:2449-2462`）。
3. 重试一致性 → 无 seed，提示词按轮次改写，不满足要求。
4. 相邻镜头校验 → 只有场景 warning，无角色校验、不阻断。
5. 图生视频是否收到动作 → **是**（effective_prompt 已证明）。
