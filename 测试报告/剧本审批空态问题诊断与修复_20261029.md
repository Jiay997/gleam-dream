# 剧本审批空态问题诊断与修复

| 项目 | 内容 |
|---|---|
| 日期 | 2026-10-29 |
| 截图页面 | 剧本审核 `/projects/:projectId/script/review` |
| 截图现象 | 页面显示「当前没有待确认的剧本 / 剧本生成 · 改写完成后，审批单将出现在这里（有效期 7 天）」与「返回审批台」按钮 |
| 结论 | 空态本身是合法状态，但缺少**原因诊断与下一步**；同时发现**手动提交审核不创建审批单**、**查询未按关口类型过滤**、**旧版本审批历史干扰诊断**三类真实问题，已修复并验证 |

---

## 1. 图片中的具体问题

### 问题 A：空态不可解释，用户被卡在“没有待确认的剧本”

- **表现**：无论项目是“没有剧本”“剧本还没提交审核”“审核已通过/已驳回/已过期”“审批单丢失”，页面都只显示同一句“当前没有待确认的剧本”，主操作只有“返回审批台”。
- **用户感受**：审批台 HITL-1 可能显示“待确认”，点进详情却空白；返回审批台又回到同一循环，找不到下一步。
- **成因**：
  1. `ScriptReviewView.vue` 空态是静态文案，未读取「当前剧本状态 + 最近审批单状态 + 项目阶段」；
  2. 空态只提供返回按钮，没有“去剧本页提交审核 / 修正 / 前往资产”等任务动作。
- **修复**：空态改为按状态诊断（详见第 3 节 F2），覆盖 10 种情形，并给出对应主操作。

### 问题 B：剧本已“待确认”，但审批台没有任何待办（核心问题）

- **表现**：
  - 审批台 HITL-1 卡片可能显示“待确认”，但实际列表可能为空；
  - 或剧本页提交审核后跳审批台，审批台没有 HITL-1 待办；
  - 直接打开 `/script/review` 永远是截图中的空态。
- **成因**：
  - 后端 `submit_script_review` 原先只执行 LLM 合规审核，把剧本状态置为 `pending_confirm`，**不创建 `ApprovalRequest`**；审批单创建只发生在上传解析（`_parse_document_flow`）或编排建单节点中。
  - 因此通过编辑器“提交审核”的剧本，状态是待确认，但没有 HITL-1 审批单。
  - 旧数据同样存在：剧本 `pending_confirm` 但项目没有 pending script 审批单。
- **修复**：
  - 新增 `_ensure_script_approval`：审核通过时幂等创建/复用 HITL-1 审批单；
  - 重复提交且审批单缺失时走“快速补齐”分支，不再重复调用 LLM；
  - 空态新增「重新生成审批单」按钮，可一键修复旧数据。

### 问题 C：审批单查询未按关口类型过滤，存在被其他待办挤出分页的风险

- **表现**：极端情况下项目同时存在多个关口待办，`/script/review` 拉取 50 条 pending 后前端再筛 `script`，剧本待办可能不在前 50 条。
- **成因**：`fetchList` 调用 `listApprovals({ project_id, status:'pending', page_size:50 })`，未传 `approval_type`。
- **修复**：改为服务端 `approval_type=script`，pending 拉 100 条；同时单独查询最近历史单。

### 问题 D：旧版本审批历史干扰当前版本状态判断

- **表现**：当前剧本是 v8/851、但项目里还留着 v6/785 的 `approved` 单；空态若直接取“最近一张单”，会误显示“剧本已确认通过”，掩盖当前版本没有审批单的事实。
- **成因**：历史未按 `target_id = current_script_id` 过滤。
- **修复**：只认当前剧本版本的审批单；查不到则按当前剧本状态诊断（缺失 → 提供补齐按钮）。

### 问题 E：入口语义与流程闭环不一致（已在上轮修复，此轮补强）

- **表现**：旧版剧本页“前往审批台确认”直接跳 `/script/review`，用户以为去了审批台，但页面是审批详情空态；审批台菜单当时叫“总览”。
- **修复**：
  - 项目内导航第一项已改为「审批台」；
  - 剧本页“提交审核”成功后统一跳审批台，再从审批台的 HITL-1 卡进入详情；
  - 优先级：审批台 → 详情页，避免详情页空态成为第一入口。

### 问题 F：项目/剧本状态数据不一致（存量数据风险）

- **表现**（本次数据库排查发现）：
  - 项目 932：`status=scripting` 但没有 `current_script_id`，任何剧本审批页都只能空态；
  - 项目 845：`status=draft` 但存在 pending `storyboard` 审批单；
  - 多个 draft 项目没有剧本，但用户可能从通知/历史链接直接进入 `/script/review`。
- **成因**：生成/上传流程中断、测试数据残留、历史状态流转未回滚，导致“项目阶段”与“产物 / 审批单”不一致。
- **修复**：
  - 前端空态会明确显示“项目还没有剧本”“剧本确认已完成”等真实原因，并给出下一步；
  - 建议运维按第 5 节只读 SQL 巡检存量数据，必要时人工修正状态。

### 问题 G：合规审核失败 / 过期无法区分

- **表现**：`rejected`、`expired`、`compliance_review` 与“从未提交”都显示同一空态，用户不知道是改稿、重新提交还是等待。
- **修复**：空态按剧本状态与最近审批单状态分别展示对应文案和主操作。

1. **部署后端**：重启 `backend/run_server.py`，使 `_ensure_script_approval` 与快速补齐分支生效。

   ```powershell
   .\.venv\Scripts\python.exe run_server.py
   ```

3. **存量数据修复（按项目逐个执行）**：
   - 打开 `/projects/{id}/script/review`；
   - 若显示「剧本已通过合规审核，但审批单缺失」→ 点「重新生成审批单」；

   - 若显示「项目还没有剧本」→ 去剧本页生成/上传。
4. **验证闭环**：
   - 剧本页提交 → 自动跳审批台；

   - 通过/驳回后分别进入资产或剧本页。
5. **清理测试数据**：验证过程中创建的审批单已删除，测试项目 982 已恢复 `asset_preparing`。

## 5. 存量数据巡检 SQL（只读，建议运维执行）

```sql
-- 1) 剧本关口阶段但没有当前剧本的项目
select p.id, p.title, p.status, p.current_script_id
from projects p
where p.deleted_at is null
  and p.status in ('scripting','script_review')
  and p.current_script_id is null;

-- 2) 剧本已通过合规审核（pending_confirm）但没有 pending 审批单
select p.id, p.title, p.current_script_id, s.status as script_status
from projects p
join scripts s on s.id = p.current_script_id
where p.deleted_at is null
  and s.status = 'pending_confirm'
  and not exists (
    select 1 from approval_requests a
    where a.project_id = p.id and a.approval_type = 'script' and a.status = 'pending'
  );

-- 3) 项目阶段与待办关口明显不一致（示例：draft 却有待审分镜）
select p.id, p.title, p.status, a.approval_type, a.status
from projects p
join approval_requests a on a.project_id = p.id
where p.deleted_at is null and a.status = 'pending'
  and p.status in ('draft','scripting','script_review')
  and a.approval_type <> 'script';
```

处理建议：第 2 类优先在页面点「重新生成审批单」；第 1 类先去剧本页生成/上传；第 3 类确认是测试残留后由 Owner 处理后端状态或清理审批单。

## 5.1 补充修复（本轮二次收口）

| 缺陷 | 表现 | 根因 | 修复 |
|---|---|---|---|
| 项目已越过剧本阶段仍显示“提交审核” | 资产阶段项目在剧本页仍可点提交，触发无意义的合规审核，且跳审批台后无待办 | 前端按钮只判断 `pendingScriptCount`，未判断项目阶段 | `ScriptEditorView` 新增 `scriptGateStage`：非 draft/scripting/script_review 时显示「剧本确认已完成 · 查看审批台」 |
| 剧本页待办计数可能被截断 | 同项目其他关口待办多时，`pendingScriptCount` 误为 0 | 拉 50 条全类型 pending 后前端过滤 | 改为服务端 `approval_type=script`、`page_size=100` |
| 审批台看不到“审批单缺失” | 用户必须进入审批详情空态才发现问题 | 审批台只在关口卡片展示“无待办” | `ProjectOverviewView` 新增 `scriptApprovalGap` 横幅：`scripting/script_review` 且有当前剧本但无 HITL-1 待办时，提示并提供「前往剧本审核页修复 →」 |
| 审批台待办分页风险 | 项目待办超过 50 条时关口计数可能不准 | 查询 `page_size=50` | 提升为 100（接口上限） |

验证：
- `982`（asset_preparing）剧本页：提交按钮 0 个，显示「剧本确认已完成 · 查看审批台」；
- `982`（临时置 script_review、无待办）审批台：出现缺口横幅，点击跳 `/script/review`，空态识别为「审批单缺失」；
- `npm run typecheck`、`npm run build` 均通过。

## 6. 后续建议

1. 将“提交审核”改为异步任务 + 审批台进度回看，避免同步 1–3 分钟无进度。
2. 增加定时巡检任务（对应第 5 节 SQL），自动告警“pending_confirm 无审批单”“script_review 无剧本”。
3. 审批台已增加“审批单缺失”横幅与修复入口；后续可把「重新生成审批单」直接内嵌到 HITL-1 卡片，减少一次跳转。
4. 统一剧本审批详情与审批台的状态来源，避免两处独立查询产生瞬时不一致。
