# 「无权限操作」问题诊断与修复报告（2026-10-30）

## 一、问题现象

截图现场：`/settings/models`（模型配置）页面顶部连续弹出 3 条 toast「暂无权限执行该操作」，
页面主体为空态「模型配置加载失败 / 暂无权限执行该操作」，只有「重试」按钮；右上角虽有
「配置管理口令」入口，但用户无法判断错误来源，反复点重试仍是同样的提示。同一时刻资产
955「陈默」处于 `qc_failed`，错误为百炼 `HTTP 401 InvalidApiKey`——用户正是想进模型配置页
排查这个"无权限"，结果自己先被挡在门外。

## 二、根因分析（四个叠加层）

| 层 | 现象 | 根因 |
| --- | --- | --- |
| 1 | 页面 403、只显示"暂无权限执行该操作" | 后端 `model-configs` **全部端点（含 GET 列表）** 依赖 `require_admin_token`，要求请求头 `X-Admin-Token` 等于 `settings.ADMIN_TOKEN`；前端 `gd_admin_token` 未配置时必然 403 |
| 2 | 用户不知道 403 的具体原因 | 前端 `api/http.ts` 的 `resolveMessage` **用通用文案表覆盖了后端 message**（`20003 → 暂无权限执行该操作`），把后端"管理端口令缺失或不匹配（X-Admin-Token）"这类可执行原因吞掉了；该码还被"仅项目 Owner 可…"等业务复用，泛化文案进一步误导 |
| 3 | 找不到配置口令的入口/入口无效 | 口令配置只用原生 `window.prompt`，被浏览器拦或用户误关后无二次入口；20003 空态只有「重试」，没有"输入口令"动作，形成死循环；「新增模型」在无口令时也能点，提交才 403，属于无效交互 |
| 4 | 资产生成持续失败（401 / ConnectError） | ① `.env` 的 `BAILIAN_API_KEY` 已失效（百炼返回 401 `InvalidApiKey`）；② Agnes 图片调用被 **Windows 系统代理**（注册表 `ProxyEnable=1, 127.0.0.1:7890`）劫持，httpx 默认 `trust_env=True` 走代理 → TLS 抛 `ConnectError`，连续失败触发熔断切到百炼 → 暴露 401 |

补充证据（Agnes 连通性对照，`trust_env` 两种模式实测）：

```
getproxies() = {'http': 'http://127.0.0.1:7890', 'https': 'http://127.0.0.1:7890', 'ftp': ...}
trust_env=True  -> ConnectError
trust_env=False -> HTTP 200 (len=1161)
```

## 三、修复实施（代码位置级）

### 1. 前端：让"无权限"从死循环变成可执行入口

- `frontend/src/api/http.ts`
  - `resolveMessage`：`20003` 优先透传后端 message（去掉泛化覆盖），其余错误码行为不变。
    ```ts
    const detail = fallback?.trim()
    if (code === 20003 && detail) return detail
    return ERROR_MESSAGES[code] ?? (detail || '操作失败，请稍后重试')
    ```
- `frontend/src/views/ModelSettingsView.vue`
  - 新增 `errorCode / unauthorized`：识别 `ApiError.code === 20003`，不再走通用 `ErrorRetryBlock` 死循环；
  - 新增页内「管理端口令」面板（`tokenPanelOpen`，未配置时默认展开）：输入 → 写入本地 → **重拉列表验证** → 成功关闭面板并提示，失败回滚旧口令（避免把错误口令留在本地导致持续 403）；
  - 20003 空态改为引导块：标题「模型配置加载失败：需要管理端口令」+ 后端具体原因 + 「输入管理端口令」「重试」；
  - 移除原生 `window.prompt`，改用面板（可重复打开/清除口令）；
  - `openCreate` 增加前置守卫：无口令时展开面板并提示，避免"能填表单但提交必 403"的无效交互；
  - 文件级注释补充 v7.2 权限说明。

### 2. 后端：错误消息自带修复指引

- `backend/app/core/deps.py` `require_admin_token`：20003 message 改为
  `管理端口令缺失或不匹配（X-Admin-Token）：请在「模型配置」页填写 backend/.env 中的 ADMIN_TOKEN`。
  仅改文案，鉴权策略（读/写都需管理口令）**保持不变**，符合 README「模型配置读/写管理端口令」约定。

### 3. 模型侧：401 与 ConnectError

- `backend/.env`：`BAILIAN_API_KEY` 替换为同工作区可用的新密钥（备份 `backend/.env.bak-20261030`，并去除 PowerShell 写入产生的 BOM）。
- `backend/app/infra/model_gateway/bailian.py`：`httpx.TransportError` 指数退避重试；401/403 输出可操作文案。
- `backend/app/infra/model_gateway/agnes.py`：同样的网络重试；**新增 `_AGNES_TRUST_ENV = False`**，
  两处 `httpx.AsyncClient` 显式 `trust_env=False` 直连（绕开失效系统代理），并在注释中记录成因。
- `backend/app/services/asset_service.py`：生成成功后清理 `meta.last_error`，避免恢复后仍显示旧错误。
- `frontend/src/views/CharacterDetailView.vue` / `AssetWallView.vue`：按错误文案区分「模型生成失败」与「相似度质检未过」，生成失败时提供「前往模型配置检查 →」。

## 五、使用指引（交付给使用者）

1. 打开「模型配置」页，页面顶部「管理端口令」面板输入服务端 `backend/.env` 的 `ADMIN_TOKEN`
   （当前开发环境值见该文件），点「验证并进入」；口令只存浏览器本地 `gd_admin_token`。
2. 口令轮换后点「更换管理口令」重新输入，或「清除口令」后刷新。
3. 若仍看到 20003，页面会直接显示后端原因（不再只有"暂无权限执行该操作"）。

## 六、遗留与风险

- 其余提供商（`bailian.py` / `qwen_tts.py` / `openai_compat.py`）仍为 `trust_env=True`：
  若本机系统代理再次失效，同样可能出现 ConnectError。本次只对实测失败的 Agnes 关闭代理探测；
  建议后续统一加 `MODEL_HTTP_TRUST_ENV` 配置项并按需切换。
- 网关仍是"单次请求命中优先级 1 的模型、失败不自动降级到候选"（降级发生在下一次请求/熔断后），
  本次未改动该设计；如需要请求内 fallback 应作为独立变更评审。
- 模型配置的读接口仍要求管理口令（与 README 约定一致）；若产品希望"登录即可只读查看掩码配置"，
  需单独讨论安全边界后调整后端依赖。
