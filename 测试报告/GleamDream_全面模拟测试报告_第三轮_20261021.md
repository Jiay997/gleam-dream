## 3. 多智能体协作功能验证

### 3.1 剧本生成链路（编剧 ↔ 合规 反馈闭环）——符合 PRD ✅

以项目 #352 一句话灵感（"外卖骑手深夜接到一份送往自己老宅的订单……"）发起 `POST /orchestration/projects/352/script-generate`，`agent_runs` 表实际取证：

| Run | 节点 | 智能体 | tokens | 积分 | 耗时 | 输出 |
|---|---|---|---|---|---|---|
| 153 | generate_outline | screenwriter | 14,911 | 5 | 81.5s | 《槐树巷十七号》 |
| 154 | generate_episodes | screenwriter | 61,516 | 47 | 198.6s | 10 集全部生成 |
| 155 | compliance_review | compliance | 13,537 | 22 | 16.2s | **verdict=flag**（第 1 轮发现合规问题） |
| 156 | generate_episodes | screenwriter（compliance_fix=true） | 19,704 | 23 | 51.2s | **定向重写第 2/3/5/8 集** |
| 157 | compliance_review | compliance | 12,723 | 21 | 16.0s | 第 2 轮 flag（交由人工终审） |

**结论**：
1. 智能体间反馈闭环真实存在：合规 flag → 编剧携带 `compliance_fix=true` 只重写受影响集（输入摘要 `affected_episodes:[2,3,5,8]`），符合 PRD「合规不合格定向局部改写」设计。
2. 计费链路与链路绑定：每节点独立结算（billing_precheck 预检冻结 → 各 run cost_credits 落账）。
3. LLM 输出 JSON 解析失败自动重试机制工作正常（日志：`attempt=0 解析失败 → attempt=1 成功`）。
4. 完成后自动创建 HITL 关口一审批单 #103（7 天有效期），项目进入 script_review。

### 3.2 前端智能体进度可视化——符合 PRD ✅

生成中页面展示五步任务规划（WRITE_TODOS）：`预算预检 → 故事大纲 → 分集与对白 → 合规审核 → 剧本入库`，配 SCREENWRITER AGENT、SAFETY SHIELD 护栏面板与「预估消耗 500 积分」提示；每 3 秒轮询项目状态。

## 6. 关键业务流程测试（端到端）

### 6.1 主流程：一句话灵感 → 成片（项目 #352 实测）

```
灵感输入 → 四步创建向导(#352) → 一句话生成剧本(五步智能体链路, 6m06s, 74 credits)
→ HITL-1 approve(#103, 结算 1 积分) → 智能规划资产(35 个) → 四视图生成+approve+lock(35/35)
→ asset_review → 分镜生成(12 镜) → 锚点绑定(12/12) → 锁定+HITL-3(#104) → approve
→ 批量渲染(12/12 成功, 冻结 1140 → 全额结算, 余额 5698→4558)
→ P6 后期: TTS(4 片段)+字幕(4 条)+母版合成(202) → HITL-4(#105) → approve 202
→ ✗ 导出被拦截「时间线尚未审批通过」(D30) → ✗ 分发阻断
```

| 环节 | 结果 | 说明 |
|---|---|---|
| 灵感→剧本→关口一 | ✅ | 全智能体链路 + 结算 + 状态推进正确 |
| 资产→关口二 | ⚠️ | 后端链路通；UI 生成入口被 D18 禁用（需 API 代操作）；关口二无独立审批单 |
| 分镜→关口三 | ✅ | 锚点守卫 + 锁定 + 审批单 + approve 全通过 |
| 渲染 | ✅ | 批量编排/仪表盘/结算一致 |
| 后期→关口四 | ⚠️ | 后端 TTS/字幕/合成通；UI 首屏 D26 报错需 API 代操作；approve 后状态未回写（D30） |
| 导出→分发 | ❌ | 被 D30 永久拦截，**用户无法完成 PRD 定义的成片交付闭环** |

### 6.2 状态机符合性

PRD 定义 11 态：draft→scripting→script_review→asset_preparing→asset_review→storyboarding→storyboard_review→rendering→post_producing→final_review→completed（+archived/paused/failed）。

实测可达状态：前 7 态全部正确流转 ✅；**rendering / post_producing / final_review / completed 4 态在全部代码中无任何触发点（D28，严重）**——渲染完成、合成完成、关口四 approve 均不推进项目状态，项目 #352 全程停在 storyboard_review。总览页流程进度与实际阶段不一致。

### 9.2 核心结论

1. **多智能体协作链路（PRD 核心卖点）真实可用且符合设计**：编剧↔合规定向改写闭环、计费与链路绑定、断点挂起/恢复、失败自动重试均有实证；前端五步进度可视化完整。
2. **「生成侧」体验成熟**：从一句话灵感到 12 镜渲染成品，主链路 20+ 环节全部跑通，积分冻结-结算-解冻全程账实一致。
3. **「交付侧」是当前最大断点**：关口四审批通过后导出被拦截（D30）、母版缺失（D27）、项目状态机后 4 态不可达（D28）、后期页首屏报错（D26）——**PRD 定义的端到端商业闭环（成片→导出→分发）当前无法走通**。
4. **实时性基建缺失**：SSE 404 + 轮询 401（D22/D23），所有"实时"体验均为轮询模拟。
