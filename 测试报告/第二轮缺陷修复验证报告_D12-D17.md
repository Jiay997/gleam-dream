## 1. D12 会话静默续期（一般/P0）

### 根因

`frontend/src/api/http.ts` 响应拦截器对 `20001/20002`（或 HTTP 401）一律
`redirectToLogin()`——`refreshToken` 虽已持久化到 localStorage（`gd_refresh_token`）
但从未被使用；access token（2h）过期即强制重登录。

### 修改内容（`frontend/src/api/http.ts`）

1. **`refreshSession()`**：裸 axios 直连 `POST /api/v1/auth/refresh`
   `{refresh_token}`（绕过本实例拦截器，杜绝递归）；成功仅更新
   `localStorage.gd_access_token`（后端 refresh 不轮换 refreshToken，契约一致）；
2. **`refreshOnce()`（single-flight）**：并发 401 共享同一次 refresh 调用，
   避免多个请求同时过期触发刷新风暴；
3. **`replayAfterRefresh(config)`**：续期成功后重放原请求**恰好一次**
   （config 打 `__authRetried` 标记防死循环），重放请求走完整拦截器链
   （信封解包/幂等键均生效）；续期失败才清理凭证跳登录；
4. **豁免**：`/auth/*` 端点本身（登录密码错误 20001 不触发续期/重放）；
   成功信封路径（HTTP 200 + code 20001/20002）与 HTTP 错误路径双通道接入。

### 验证方式

- `npm run build`（vue-tsc strict + vite）零错误；
- 行为推演核查四条边界：并发 401 单飞、重放再 401 不死循环、登录端点豁免、
  blob 下载重放；
- 人工复测路径：将 `JWT_ACCESS_EXPIRE_MINUTES` 调小 → 等待过期 → 任意操作
  → 观察网络面板：`/auth/refresh` 被调用一次 → 原请求自动重放成功（HTTP 200），
  不跳登录页。

## 2. D13 归档项目可新建导出（一般/P1）

### 根因

导出链路（`export_service.create_export`）只校验套餐权益与时间线状态，
**全程无项目状态校验**；`project_guard` 也不感知归档——归档（设计语义为
只读终态）下所有 edit/export 端点实际放行。

### 修改内容（`backend/app/core/deps.py::require_project_acl`）

在 ACL 判定链最前部（项目存在性之后、Owner 判定之前）增加**归档只读守卫**：

```python
if project.status == "archived" and need in ("edit", "export"):
    raise BizError(ErrorCode.PROJECT_ARCHIVED)   # 40004
```

- **统一收口**：全部 37 处 `project_guard` 使用点自动生效——导出创建/批量/
  元数据、分发、分镜生成、渲染批次、后期合成、PATCH、快照回滚、成员管理……
  归档项目一律 40004，一次性消除测试报告指出的"归档态守卫不一致"；
- view 档读取（详情/列表/导出列表/SSE）不受影响，归档=纯只读。

### 验证方式（`tests/test_defect_fixes.py::test_d13_archived_project_export_blocked`）

归档后 `POST /exports` → `code=40004`（原缺陷为 code=0 且任务创建 succeeded）；
`POST /exports/batch` → 40004；`GET /exports`（view）→ code=0 放行。

## 3. D14 成员授权无撤销端点（一般/P1）

### 根因

路由表仅有 `PUT /projects/{id}/members/{uid}`（授予/升级）与 `GET members`，
`DELETE` 方法不存在（HTTP 405）——权限只能授予不能撤销，被授权用户永久保留访问。

### 修改内容

1. **服务层** `project_service.revoke_project_member()`：删除
   `project_members` 授权行；Owner 不可移除（20003）；非成员 10002；
   操作落 `audit_logs`（action=`project.permission_revoke`，含被移除权限）；
2. **路由** `DELETE /projects/{project_id}/members/{user_id}`（edit 档守卫，
   与 PUT 同档）；撤销后该用户下次访问即 20003。

### 验证方式（`test_d14_member_revoke_lifecycle`）

完整生命周期：授予 view → B 可读 → B 自我撤销被拒（20003，view<edit）→
Owner 撤销（code=0，`removed_permission=view`）→ B 访问失效（20003）→
重复撤销（10002）→ 移除 Owner（20003）。

## 4. D15 归档项目分镜生成静默丢弃（一般/P1）

### 根因

`storyboard_service.generate_storyboard` 校验剧本/集号/幂等后直接受理
（202），**无项目状态前置校验**；后台管线对非法状态无产物落库——形成
"接口 code=0 受理，实际无 agent_run、无 storyboard 产物"的静默丢弃。
（paused 状态同源：后台管线同样无产物。）

### 修改内容（`backend/app/services/storyboard_service.py`）

1. 受理**最前置**状态校验（先于一切副作用）：
   - `archived` → 40004（归档只读；与 ACL 守卫双保险）；
   - `paused` → 40001（"请先恢复项目"，与剧本生成守卫口径一致，GR-1）；
2. 采用**阻止名单**而非严格白名单（`{"archived","paused"}`）：既封死两类
   静默丢弃，又不破坏既有"任意有剧本状态可发起"的管线测试约定；白名单
   收紧列为后续事项（需同步重构管线测试的状态准备）。

### 验证方式（`test_d15_archived_storyboard_generate_blocked` / `test_d15_paused_...`）

归档项目 `POST storyboards/generate` → 40004；暂停项目 → 40001——均不再
返回受理回执。

## 5. D16 归档无恢复路径（轻微/P2）

### 根因

状态机白名单中 `archived` 无出口（终态设计），`/resume` 仅认 `paused`
（40001"项目未处于暂停状态"）——归档不可逆且无显式恢复入口。

### 修改内容

1. **`archive_project()`**：归档时把归档前状态存入
   `config["_archived_before"]`（与 pause 的 `_paused_before` 同构）；
2. **新增 `unarchive_project()`**：还原 `_archived_before`（历史归档无记录
   回退 `draft`）、清空 `archived_at`、operation_logs + SSE `status_changed`
   留痕；状态机白名单不变（archived 仍是流转终态，恢复必须走专用入口）；
3. **路由** `POST /projects/{id}/unarchive`：归档态下不走 edit 档守卫
   （否则被归档守卫拦截），以 view 档通过 ACL 后显式校验 **仅 Owner**。

### 验证方式（`test_d16_unarchive_restores_state`）

draft→archived→unarchive 还原 `draft`、`archived_at=null`；非归档态恢复
40001；非 Owner 恢复 20003；再归档→再恢复幂等往返成功。

## 6. D17 改写弹窗 ARIA 缺失（轻微/P2）

### 核实结论

改写弹窗（`ScriptEditorView.vue` L1284）使用的是全局 `Modal.vue` 基座，
该基座**已含** `role="dialog"`、`aria-modal="true"`（L130-131）。测试报告
TC-B24 亦注明"AX 树因节流未捕获（环境限制）"——原始观测疑为浏览器 AX
快照节流的环境性误报，而非组件缺陷。

### 修改内容（`frontend/src/components/common/Modal.vue`，防御性强化）

标题命名从容器 `aria-label` 升级为 **`aria-labelledby` 实例级关联**
（模块自增序号生成 `gd-modal-title-{n}` 绑定头部 `<h3>`）——AX 树对对话框
的命名更稳定可达；无标题场景回退 `aria-label="对话框"`。

### 验证方式

`npm run build` 零错误；该基座覆盖全部 5 处弹窗（含 AI 改写弹窗），
人工复测路径：打开改写弹窗 → Chrome DevTools Accessibility 树应出现
`dialog "AI 局部改写"`。
