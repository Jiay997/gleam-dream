01 · 资产设计页：资产列表被挤出视口且整页不可滚动

页面 / 组件/projects/151/assets · 资产设计页资产列表区（用户点名滑动异常页）
问题类型滚动失效 / 纵向空间分配错误 / 内容不可达
具体描述 页面根容器为 flex h-full flex-col overflow-hidden，页头（约 391px）、质检统计（约 538px）、筛选区（约 179px）全部 shrink-0，仅底部列表使用 min-h-0 flex-1 overflow-y-auto。几何测量：列表容器 scrollHeight=14723、clientHeight=36，其 top=1216（视口高度 554）；同时 main 的 clientHeight = scrollHeight = 414、documentElement.scrollHeight = 554，即主容器与页面均无滚动余量。结果：29 张资产卡片全部位于视口之外，滚轮操作无任何位移，用户只能看到筛选按钮而无法浏览/选择资产。
截图首屏仅渲染到搜索/批量审核/导出按钮，下方列表区域为空；滚动后画面无变化。
改进建议 ① 将页头 + 质检统计 + 筛选区合并进一个可滚动容器，列表不再单独承担滚动；或给统计区设置可折叠/紧凑模式（矮屏下折叠为 1 行摘要）。
② 把根容器改为 flex h-full min-h-0 flex-col 并让 main 承担滚动，列表区设置 min-h-[240px] 兜底。
③ 对 @media (max-height: 700px) 增加紧凑断点，压缩页头与统计区间距，避免固定块累计超过视口。
参考代码：AssetWallView.vue:923、AssetWallView.vue:1197。

02 · 模型配置「新增模型」弹窗：超高且不可内部滚动

页面 / 组件/settings/models · 「新增模型」弹窗（含遮罩、表单、底部操作栏）
问题类型弹窗溢出 / 操作不可达
具体描述 Modal 遮罩为 fixed inset-0 flex items-center justify-center，panel 无 max-height，且 .gd-modal__panel 设置了 overflow: hidden。实测 panel top=-284.4、bottom=838.8、height=1123.2，视口高度 554：顶部「模型类型 / 显示名称」等必填字段被裁到屏幕外，底部「取消 / 创建配置」按钮同样不可见，默认 overflow-y: hidden 且鼠标滚轮无效。用户无法完整填写或提交表单，新建模型流程被完全阻断（仅强制注入 overflow:auto + max-height 后才能操作）。
截图左图：默认打开状态，顶部字段被裁、底部按钮不可见；右图：强制滚动后可见完整表单。
改进建议 ① .gd-modal__panel 增加 max-height: calc(100vh - 32px)，并改为 display:flex; flex-direction:column; overflow:hidden；② 表单主体区设置 flex-1 overflow-y:auto，底部操作栏固定不滚动；③ 弹窗内边距在 max-height:700px 时收紧。
参考代码：Modal.vue:150、aurora.css:1561。

五、视觉风格一致性评估

评估项结论说明
主题与色彩统一全局深色底 + 极光渐变高光，紫/青/玫红/琥珀语义色稳定；无浅色块突兀出现
字体层级统一衬线刊头 + 无衬线正文，页面标题字号层级一致；分镜卡片 30% 缩放时文字可读性下降（属画布缩放特性，已有窄屏降级提示）
组件形态统一圆角 12–16px、1px 描边、玻璃拟态一致；按钮高光与描边风格统一
密度与留白偏差资产设计、生成任务中心、剧本页首屏密度显著高于总览/计费页，纵向留白分配失衡
浮层与弹窗偏差缺少统一的高度约束与滚动策略；Toast 与顶栏操作区位置冲突；HITL 固定卡未预留安全间距
文案与格式偏差时间格式混用、个别指标文案直接暴露内部术语、英文副标题断行

六、修复优先级建议

  1. 第一批（阻断体验，建议立即修复）：01 资产页滚动、02 弹窗高度约束。两者均导致核心操作无法完成，且修复成本低（容器约束 + 溢出策略）。
  2. 第二批（核心内容可见性）：03 后期预览、04 剧本正文、05 分镜 HITL、06 生成任务列表、09 角色详情遮挡。建议统一抽象为「页面纵向空间分配」规范：固定区块总高不得超过视口的 45%，列表区最小高度 280px，滚动只由一级容器承担。
  3. 第三批（细节与一致性）：07 面包屑、08 占位资源、10 Toast 位置、11 导航溢出、12–16 文案与格式。

说明：本次测试在 606×554 窄屏/矮屏下进行，问题 01–06、11、14 均为响应式空间分配缺陷，在 ≥1280×800 桌面视口下可能不复现；但演示与大屏投屏常用宽屏，建议按「小屏可用、大屏更佳」的双端标准修复，避免仅做视口隐藏。
