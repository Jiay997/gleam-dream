## 二、回归中发现的致命缺陷（回归新增修复）

### 【R-001】CPython list.sort 排序期间清空列表 → 路由崩溃 10003（P0）

- **现象**：回归阶段 TTS preview 与 LLM 路由随机抛 `10003`（`min(prices)` 对空集合取 min 抛 ValueError）。首次 1411 剧本生成亦因此失败。
- **根因**：`router.pick_models` 的 `candidates.sort(key=lambda item: _score_model(item, candidates))` —— key 闭包引用**被排序的列表本身**。CPython 的 list.sort() 在排序期间会把列表临时清空（元素先搬入临时数组，排序完成后回填），key 函数在此期间读到空列表。字节码反汇编看似正常，id 探针实证：同一对象排序外 len=2、排序期间 len=0。
- **修复**：[router.py](file:///e:/FeiSi/Project%20code/gleam-dream/backend/app/infra/model_gateway/router.py) `pick_models()` 先算分再排序：`scored = [(_score_model(item, candidates), item) for item in candidates]` 后对二元组排序；`_score_model()` 增加 `unit_price_credits or 0.0` 与空候选集防御。
- **验证**：1411 剧本生成（LLM 路由 deepseek-flash）、TTS preview（qwen-tts 真实合成）全部走通；重启后连续 3 次路由无 10003。

### 【R-002】Windows ProactorEventLoop 与 psycopg 不兼容 → checkpointer 建池失败 → 剧本生成必失败（P0）

- **现象**：1411 剧本生成报 `couldn't get a connection after 30.00 sec`；后端日志 `psycopg.pool: Psycopg cannot use the 'ProactorEventLoop' to run in async mode`，连接池 300s 重连失败，pool worker 任务被销毁。
- **根因**：psycopg3 异步模式要求 SelectorEventLoop；uvicorn 在 Windows 默认（无 --reload）使用 ProactorEventLoop，且事件循环在 `config.load()`（import app）**之前**创建，应用代码内的 policy 切换无效。
- **修复**（三层防御）：
  1. [run_server.py](file:///e:/FeiSi/Project%20code/gleam-dream/backend/run_server.py)：启动入口在事件循环创建**之前**注入 Selector 循环工厂（uvicorn 0.36+ `loop` 参数）；
  2. [app/loop_factory.py](file:///e:/FeiSi/Project%20code/gleam-dream/backend/app/loop_factory.py)：新建，提供 `selector_loop_factory()`；
  3. [app/graphs/checkpointer.py](file:///e:/FeiSi/Project%20code/gleam-dream/backend/app/graphs/checkpointer.py)：模块加载时兜底切换 policy（覆盖 reload 子进程等场景）。
- **验证**：重启后启动日志无 psycopg 警告；`checkpointer 初始化完成` 日志正常；1411 剧本生成 202 → script_review 走通（13:03:31 episodes 完成、13:03:43 合规审查完成）。

### 【R-003】storyboards 列表接口不含 shots（文档化，非缺陷）

- `GET /projects/{pid}/storyboards` 只返回分镜板元数据，shots 需二段取 `GET /storyboards/{sb_id}`。Playwright fidelity spec 已按两步取详情修正（与 step0b 一致）。

### 【R-004】合成首帧底部黑带 → 渲染 QC black_block 拦截 5/23 镜（P0，系统性）

- **现象**：1411 渲染首轮 5 镜（shot1272/1289/1300/1308/1320）被 QC 以 `black_block` 拦截升级 manual_required；溯源发现合成首帧底部存在黑带，且 I2V 继承后放大。
- **根因**：Agnes 文生图输出的场景资产图自带底部近黑边框，实测黑带高度 19.8%~27%（资产版本 1156=27%、1158=21.6%、1159=19.8%；1157 干净）。`_trim_dark_border` 旧参数 `threshold=18/limit=0.14` 只能裁掉不足一半，且黑带含 18~24 亮度行漏过旧阈值。残留黑带进入合成首帧后被 I2V 继承放大，触发渲染 QC 拦截。
- **修复**：[frame_image_ops.py](file:///e:/FeiSi/Project%20code/gleam-dream/backend/app/services/frame_image_ops.py) `_trim_dark_border` 调整为 `threshold=25/limit=0.32`（覆盖 27% 极端黑带与 18~24 亮度行）。
- **验证**：1156/1158/1159 三图裁剪后底带残留 0%；重合成 5 镜首帧底部残留 0~0.16%（PIL 逐行校验）；retry 5 任务后 **23/23 全部 succeeded**；成片抽帧人工复核 shot1308/shot1320 无黑带、画面完整、AI 水印正常。

### 【R-005】manual_required 任务 retry 必崩 500（10003）（P1）

- **现象**：R-004 修复后对 5 个 manual_required 任务执行重试，全部返回 10003（500）。
- **根因**：[render.py](file:///e:/FeiSi/Project%20code/gleam-dream/backend/app/api/render.py) retry 端点曾用 `Project(id=task.project_id)` 构造仅含 id 的轻量 ORM 实例；manual_required 任务（4 轮执行器重试耗尽）冻结必然已释放，`retry_task` 读 `project.owner_user_id` 重新预检冻结时读到 None 直接 TypeError。
- **修复**：retry 端点改为 `session.get(Project, task.project_id)` 完整加载项目记录（缺失则 10002）。
- **验证**：5 任务重试全部成功入队并最终 succeeded。
